# Hopper (H200 / SM_90)

Minimal kernel-dev structure mirroring `../Blackwell`, targeting Hopper (SM_90a).

```
Hopper/
├── CMakeLists.txt              # single target: gqa_bwd (arch 90a)
├── include/utils/              # shared helpers (copied from Blackwell)
│   ├── kernelUtils.cuh         #   CUDA_CHECK, loadBin, reportPrecision, checkResult
│   └── kernelBench.cuh         #   timing helpers
├── src/attention/GQA_bwd.cu    # first kernel: GQA backward, V1 + V2
├── precision/baseline_gqa.py   # PyTorch/Triton reference + baseline (device-agnostic)
└── data/                       # gqa_*.bin reference files (generated by baseline)
```

## GQA_bwd.cu — versions

Both are portable WMMA implementations (SM_70+ ISA, no `wgmma`/`tcgen05`/TMA),
so they run unchanged on H200:

- **V1** — `Br=16, Bc=32`, single warp (32 threads) per block.
- **V2** — `Br=64, Bc=64`, 4 warps (128 threads) per block.

Config: `B=8, Hq=12, Hkv=4, S=4096, D=64` (GQA G=3), bf16 in/out, fp32 accumulate.
Each version's `dQ/dK/dV` is checked against the PyTorch bf16 SDPA autograd reference,
then benchmarked (median over 100 L2-flushed iters, ms + TFLOP/s). The TFLOP/s use the
same `4×forward` FLOP convention as `baseline_gqa.py`, so they compare directly to the
SDPA / Triton backward numbers that script prints.

## Run

```bash
# 1. Generate the reference .bin files (needs a CUDA GPU + torch + triton)
python precision/baseline_gqa.py

# 2. Build and run the CUDA precision test
cmake -S . -B build
cmake --build build -j
./build/bin/gqa_bwd
```
